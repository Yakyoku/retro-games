# AEGIS RELAY 音の資料（音イベント対応表・音源一覧・検証結果）

この作品は Claude（Claude Code のクラウドセッション）で制作しました。

## 方針

- 曲・効果音はすべて**この作品のために新しく作ったもの**。既存作品の曲の採譜・編曲・再合成ではなく、録音や抽出した音源も使っていない。
- 依頼文にあった「1984 年の作品の原音に忠実な再現」と、原音との聴き比べはお引き受けしていない（docs/SPEC.md §0）。このため「原音との比較結果」の欄は**対象外**。
- 音の作りは「1984 年ごろの業務用基板によくある制約」を想定した独自の設計にした。矩形波 3 声（デューティ比 12.5/25/50%）＋ノイズ 1 声に加え、効果音用に矩形波 1 声とノイズ 1 声。特定のチップの再現ではない。
- 効果音が鳴っている間は、曲の ch2（内声）と ch3（打楽器）を効果音に譲る。同時に鳴る声の数が決まっているので、どれだけ撃っても音は割れない。
- リバーブ、ステレオの広がり、ドップラー効果、距離による減衰は使わない（モノラル）。3D 版・VR 版でも同じ音にしている。

## 再生のしくみ

- 曲は AudioContext の時計で 0.18 秒先まで予約する（40ms ごとに補充）。テンポは描画のフレームレートと関係しない。
- ポーズ・タブを隠す・設定画面: `ctx.suspend()`。再開すると止めた位置から続く（予約の取り直しはしない → 二重再生しない）。
- 最初の操作（クリック・キー・タップ・VR 開始）で音を有効にする（ブラウザの自動再生制限）。
- 全体・曲・効果音の音量と消音は設定から変えられ、ブラウザ内に保存される。重要な情報（被弾・ボーナスの成否など）は画面の文字・光でも伝えている。

## 検証結果（docs/verification/）

ヘッドレスの Chromium で、ゲームと同じ音源（engine.js）の**実際の出力**を PCM で録音し、数値で調べた（audio-results.json、spectrograms.png）。

| 確認したこと | 結果 |
|---|---|
| 音割れ（|x|≥0.999 のサンプル） | 全録音で 0。撃破・射撃などの効果音を 16ms ごとに 32 個ずつ 0.7 秒間重ねても、ピークは 0.354 |
| クリック（隣り合うサンプルの差 > 0.5） | 全録音で 0 |
| 曲の途中の途切れ | 曲の途中に 50ms を超える無音はなし |
| ポーズ → 再開 | 止める前と再開後の音量（RMS）は 0.067 と 0.064（二重再生なら約 2 倍になる） |
| ループの継ぎ目 | 模擬の AudioContext で時計を不規則に進めながら、3 周目までの**全音符の発音時刻が楽譜と誤差 1ns 未満で一致**（tests/audio-schedule.test.js） |
| 録音上のループの一致度 | 1 周目と 2 周目の音量の包絡の相関は 0.83〜0.98（ずらして合わせた場合）。録音では 2 周目が 20〜30ms ずれて見えたが、ずれ幅が場所ごとにばらつき、上の予約テストでは誤差がないため、コンテナ内の録音経路（ScriptProcessor）の取りこぼしと判断 |

**試聴について**: このセッションではスピーカーで音を聞けない。音色・音量のつり合い・曲の印象は、人の耳では未確認。Quest 3 実機・iPad 実機での再生も未確認。
