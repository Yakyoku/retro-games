# SOUND_REPORT — 地底探検：ポンプ・パトロール（PUMP PATROL）の音

この作品の曲・ジングル・効果音・環境音はすべて今回の書き下ろし・自作の合成音です。
ナムコ『ディグダグ』（1982 年・アーケード）の**遊び方と、音とゲームの状態の結びつけ方**（歩いている間だけ曲が進むなど）は参考にしましたが、
旋律・ジングル・録音された音は写していません。Claude は音を聞くことができないので、「聞き比べた」「聞いて確かめた」ことは一度もありません。

## 2. 音源のしくみ

- `shared/audio/wsg-core.js`: 自作の波形メモリ音源。32 ステップ × 4 ビットの波形表 9 種類（`waves.js`。矩形・パルス 25%・のこぎり寄り・三角・オルガン・中空・ベース・正弦・ノイズ表）、
  声ごとの周波数・音量（4 ビットの段）・波形、音量の減衰、ビブラート、周波数の指数スライド、周波数をでたらめに跳ばすノイズ風の音、トレモロ。
  曲の順送り（MML から作ったイベント列）と環境音もこのクラスの中で動く。命令は `at`（サンプル番号）付きで送ればサンプル単位で予約できる。
- 声の数: **曲 3 声（原作の基板と同じ数）+ 効果音 4 声**。効果音用の 4 声は**時代の基板からの意図的な逸脱**で、効果音が曲の声を奪わないようにするため。
  ジングルは曲の 3 声を使い、その間は面の曲を位置ごと保留して、終わると続きから再開する。
- クリック対策: 音量の段の切り替わりを 1.5ms でならす（音の出始め・切れ目・歩き停止のすべて）。全体の音量変更は 20ms でならす。
- 出力: 波形の読み出しを 2 倍の細かさで平均 → 9kHz の 1 次低域通過を 2 段 → 直流除去 → リミッター（0.85 を超えたら即座に下げ 0.12 秒で戻す）→ 0.9 を超える部分だけやわらかく丸める安全装置（NaN は 0 にする）。
  主な音色に残響はかけていない（環境音のしずくだけに薄いこだま）。
- 実行: `AudioWorkletProcessor`（`wsg-worklet.js`、`audioWorklet.addModule(new URL('./wsg-worklet.js', import.meta.url))`）。
  使えないときは `ScriptProcessorNode` で同じ `WSGCore` をメインスレッドで動かす。
- 鳴りっぱなし防止: 曲の音は発音の長さ（ゲート）が切れると必ず止まる。効果音は区間を最後まで進めると声を返す。`stopAll` は全部の声・曲・予約・環境音を止め、待っているジングルの Promise も解決する。

## 4. 独自性の確保

- 旋律はすべてこのセッションで書き下ろした（`tracks.js` の MML）。原作の曲を聞いていない・採譜を見ていない状態で、和音進行（C–F–G など一般的なもの）から旋律を組み立てた。
- 波形は数式から作った（原作の PROM のデータは使っていない・読んでいない）。
- 取り入れたのは「形式」と「仕組み」だけ: 32 ステップ × 4 ビットの波形メモリ・3 声・4 ビット音量・歩いている間だけ進む曲・効果音の種類。
- テストで、面の曲 3 つとタイトル・練習面の主旋律がすべて違うことを確かめている（自作どうしの重複の確認で、原作との比較ではない）。

## 5. 実際に行った確認

- `node --test tests/*.test.js`（17 項目すべて成功）: MML の読み取り、全ループ曲の 3 声が同じ長さで小節の整数倍（すべて 8 小節 = 1536 ティック）、小節線の位置、ジングルが有限の長さ、一覧の全項目に実装があること（逆も）、効果音が互いに違う設計であること、pump-air が段階ごとに高くなる設計、
  全曲を Node で 6 秒書き出して NaN なし・ピーク < 0.99・直流 < 0.01、歩き連動（止めた直後 10ms の最大段差が通常演奏の最大段差以下・30ms 後には無音・位置が進まない・同じ位置から再開）、ループのつなぎ目、ジングルの終わりの知らせの時刻、全効果音の書き出し、
  効果音が曲の声を使わないこと、最後に鳴りっぱなしの声がないこと、`stopAll` 後の無音、掘る音の間引き、環境音が曲の半分未満の大きさ（RMS）、ミュート、Web Audio のない Node で `createAudio()` が例外を出さないこと。
- `node tools/audio-render.js [フォルダ]`: 全部の曲・ジングル・効果音・環境音を書き出して数値を表にする（WAV も書き出せる）。今回の結果（48kHz・既定の音量）:
  曲のピーク 0.25〜0.33・RMS −19〜−22dBFS、環境音の RMS −42〜−48dBFS、効果音の RMS は −22〜−35dBFS（dig −49、step −47。fire-charge は −22 で最も大きい部類）、すべて NaN 0、直流 1e−4 未満。
  1 サンプルで 0.25 を超える段差（クリックの目安として数えたもの）は、全曲・全ジングル・全効果音・環境音・0.37 秒ごとに歩く/止まるを 22 回切り替えた書き出しのすべてで 0 回。
  全音量最大で全効果音を 0.05 秒おきに重ねた最悪の場合はピーク 0.85（リミッターが効いた）で、段差 0.25 超は 151 回（ノイズ系の音が重なった大音量のため）。書き出しの速さは実時間の 100〜300 倍程度（Node）。
- pump-air の段階 3〜5 を書き出して自己相関で音の高さを見積もると約 318 / 400 / 500Hz と上がっていた（段階 1・2 は見積もりがオクターブずれて信用できない値だった）。
- ヘッドレスの Google Chrome 153（Linux）で `sound-test.html` を開き、AudioWorklet 経路で `running` になること、曲を流して「歩き続ける」を切ると位置表示が止まって進まないこと、全効果音とジングルのボタンを押しても `window.__errors` が空であることを確かめた。
  `AudioWorkletNode` を消した状態でも ScriptProcessor 経路で同じ確認をした。音が実際にスピーカーから出たかは確かめていない（ヘッドレスなので）。

## 6. 確かめていないこと

- 原作のアーケード版との聞き比べ（できない。していない）。
- 実機での再生: デスクトップの Safari・Firefox、iPad の Safari（マナーモード時・電話の割り込み `interrupted` からの復帰を含む）、Meta Quest Browser（XR セッション中・終了時）。
- 聞いたときの大きさのつり合い（曲・効果音・環境音の聞こえ方）、fire-charge が予告として十分に目立つか、pump-air が「ゴムっぽく」聞こえるか、pop がかわいく聞こえるか。数値（RMS）でしか比べていない。
- 古い Safari の AudioWorklet のモジュール内 `import` がすべての版で動くか（動かなければ予備経路になる設計）。
- 長時間（数十分）の連続再生。
