# サウンドの改善 S01〜S30 — 実装の記録

この作品は Claude（Claude Code のクラウドセッション）で制作しました。

docs/UPGRADE.md「C. サウンド」の 30 項目について、何をどこに実装したかの一覧。設計の全体と計測値は docs/SOUND.md。
**人の耳では試聴していない**（制作環境で音を聞けないため）。確認はすべて、実際の出力の録音を数値とスペクトログラムで調べたものと、自動テスト（40 件）による。

## 正直な注記（できていないこと・弱いところ）

- **試聴していない。** 音色の好み、主旋律が「耳に残る」か、効果音と曲のつり合いは、数値では決められない部分が残る。音量の比は声部ごとに録って合わせたが、耳での調整が必要になる可能性が高い。
- S22「ブレイク」: 完全に音が抜ける小節は作っていない。B セクションでドラムを半分のテンポ感にして密度を落としている。
- S23: 緊張の層は音量の変化が小さい（区間の RMS でほぼ同じ、2k〜8k の割合が約 3dB 増える程度）。時刻どおり鳴っていることは確認済みだが、目立ち方は耳で要確認。
- S19: クラシック音源にはステージ曲 C が無く、A と同じ曲になる。ハイスコアもクリアと同じ曲。
- S21: ハイスコアのジングルは、ゲームオーバーの瞬間に「それまでの最高点を超えているか」を sound-map.js で判定して鳴らす（shared/app.js を変えずに済ませるため）。デバッグ指定（?debug）のプレイでも鳴る。
- 曲のセクション間の音量差は 1dB 未満（コンプレッサーでそろう）。
- 波形の事前計算（約 0.65 秒）は最初の操作の前に 6ms ずつ進めるが、ページを開いてすぐ操作すると残りをその場で計算する。Quest 3 での所要時間は未計測。
- 画面の処理が 0.5 秒以上止まると、その間に鳴るはずだった短い音は鳴らさずに進む（遅れて固まって鳴るのを避けるため）。コンテナのソフトウェア描画の 3D 版ではこれが起きた。実機では未確認。
- Quest 3・iPad の実機では未確認。Safari の一部ではリードのビブラートが省かれる。
- 旧音源の出力は 0.55 倍 → 0.85 倍に上げた（モダンとの音量差を 10dB → 6dB に縮めるため）。音色は変えていない。
