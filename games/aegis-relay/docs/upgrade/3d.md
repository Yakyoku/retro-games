# AEGIS RELAY 品質向上 — 3D / VR 版の実装結果

この作品は Claude（Claude Code のクラウドセッション）で制作しました。

docs/UPGRADE.md の項目のうち、3D 版（通常画面＋ WebXR）で受け持った分の実装結果です。
対象: キャラクター C01〜C30、背景 B01〜B30、滑らかさ M01〜M04・M07・M08・M10・M11・M14〜M16・M18・M24・M27〜M29（M12・M13・M25・M26 は 2D 用だが、考え方を 3D にも適用）。
ルール・判定・得点は変えていない（shared/ は読むだけ。見た目の高さ・揺れ・押し戻しは判定に入らない）。
モデル・画像のファイルは 1 つも使っていない。形・テクスチャ・シェーダーはすべてコードから計算で作る。意匠はこの作品の独自のもの。

## 0. 確認できたこと・できていないこと（先に）

- 確認はすべて**コンテナ内の Chromium（ソフトウェア描画・SwiftShader）**と、Meta の WebXR エミュレーター（IWER の Quest 3 設定）で行った。
  **Quest 3 の実機、実物の GPU を積んだ PC・4K ディスプレイでは一度も動かしていない。**
- したがって FPS・フレーム時間・「シェーダーの準備 ○ms」「地形 ○ms」は実機の性能を表さない（ソフトウェア描画は実機より 1〜2 桁遅い）。
  性能の目安として信頼できるのは**描画回数と三角形の数**だけ（§4）。Quest 3 で 90Hz を保てるかは未確認。
- 見た目は、通常画面 1600×900・3840×2160、XR（エミュレーター）のスクリーンショットを自分で見て調整した（docs/verification/up3d-*）。
  動いている様子（炎のゆらぎ、合体の一連の動き、ワープの筋の速さ、揺れの感じ）は静止画でしか見ていない。
- XR エミュレーターの画面は 1 枚の広い視野で、実機の両眼の見え方・距離感・文字の読みやすさとは違う。

## 6. できていないこと・割り切ったこと・心配な点

- **Quest 3 実機で未確認**。心配なのは描画回数より画素の重さ: PBR（環境マップ）＋ 4 枚のクリップ面＋半透明の層（雲 2 枚・奥の星雲・爆発）を両眼で描く。重い場合は「軽量」（雲の上の層なし、粒・星・岩・結晶を約半分、地形の格子を粗く、星雲 1024、描画バッファ 0.8 倍、72Hz、通常画面はブルームなし）を使う。それでも足りるかは実機で測るまで分からない。
- 星雲の焼き直し（エリアの切り替え時）は 8 フレームに分けたが、1 帯ぶんでも Quest の GPU で 1 フレームを超えるかもしれない（ワープの白い光の最中に行う）。最初の 1 回（起動時）は一度に焼く。
- 遺跡の陰は地表の頂点色に入れた丸いぼかしで、形の通りの影ではない。空の物体の影も丸い（リアルタイムの影は使っていない）。影は遺跡や標的の上にも落ち、VR でごく低い角度から見ると手前の枠に少しかかることがある。
- 回転体の「残像」は回る光の板で、本当のモーションブラーではない。
- 導線（B18）がつなぐのは同じ島の上の砲台・トーチカ・格納庫だけ。大陸の外に置かれるパネル・格納庫は、下面の竜骨で「浮いている台」に見せた。
- 盤面の縁で切られた島は、断面が中空（殻）に見える。崖を両面描画にして岩の内側が見えるようにしただけで、断面にふたはしていない。
- 敵の「ワープイン」は盤面に入った瞬間の演出（敵は盤面の外で生まれるため）。押し戻し・引き伸ばしは見た目だけで、判定の位置は変えていない（最大 1.4 単位、0.1 秒ほど）。
- ブルームは通常画面だけ。カメラを極端に寄せると（検証用のズーム）金属の映り込みが白く飛ぶことがある。通常の視点では起きないことを確認した。
- VR の HUD・メニュー（vrui.js）の見た目は従来のまま（毎フレームのオブジェクト生成だけ取り除いた）。
- 自動画質（M27）で下がるのは解像度だけ（仕様書 §6 のとおり）。ブルームの有無は自動では変えない。
- 周回の色相の変化（B27）は、エリア 3 の 2 周目の空を 1 枚確認しただけ（up3d-loop2.jpg。星雲の 8 分割の焼き直しもこのときに通る）。
- タイトル画面は、エリア 1 の大陸をゆっくり流し、その上を自機が飛ぶ（通常画面ではメニューの後ろに見える）。

## 7. 共有コードへの連絡（こちらでは変更していない）

- **shared/audio/engine.js**: AudioContext が 44.1kHz のとき、`unlock()` → `ensure()` の ConvolverNode で「buffer の 48000Hz が context の 44100Hz と合わない」という例外が出て、続く `se()` も失敗し、ゲームを開始できない（コンテナの Chromium の既定は 44.1kHz）。検証スクリプトでは AudioContext を 48kHz に固定して回避した。残響のバッファを `ctx.sampleRate` で作る必要がある。
- 追加してほしい addon・共有コードの変更はない。`g.pscroll` は使っている（無いときは 1 tick ぶんを引く）。
- 検証用に `window.__world`（world3d の戻り値）と `window.__cam`（通常画面のカメラの基準位置。寄せて撮るため）を足した。`__stats()` は calls / tris に加えて allCalls・mem・programs・world（準備の時間）・jobs を返す。
