# CLAUDE.md — Sky Climber VR（games/sky-climber/）

この作品は Claude（Claude Code のクラウドセッション）で制作しました。決定事項・調整値・判断ログ・検証結果・未確認事項をここに残す。

## 目的と対象
『クレイジー・クライマー』の「左右の手を独立して動かして登る」「窓・落下物・鳥を読んでよける」遊びを、Meta Quest 3 の没入型 WebXR と
通常ブラウザーの 3D（4K の大画面を想定）で遊べる形に発展させる。対象は制作者本人（大人）。PROCESS.md §9 は適用しない。

## 判断ログ
- 2026-11-12 依頼は Unity での制作だったが、クラウド環境に Unity Editor がなく、起動・ビルドには藤田さんの Unity ID のライセンス認証が要る（安全に受け取る手段がない）。
  retro-games の公開手順も three.js 前提のため、AskUserQuestion で確認し「three.js WebXR で制作」の回答を得た。Unity のプロジェクト・C#・Unity ビルドは**作っていない**
- 2026-11-12 作業ブランチはシステム指定の claude/quirky-heisenberg-yfx39d（ルート CLAUDE.md の「main に直接」より、このセッションの指定を優先）
- 2026-11-12 単位はメートル、壁の表面 z=0、プレイヤーは +z 側。1 階 2.6m・窓の列 1.7m。保持点は 1 階あたり帯・窓台・窓枠の中段・上枠の 4 段（間隔 0.56〜0.72m）。窓が広く空く所には雨どいの留め金（0.62m ごと）と看板の縁を中継に置いた
- 2026-11-12 窓は「上から下りるガラス戸」。閉まりきると窓の縁（保持点）がガラスの裏になる＝つかめない、が見て分かる。テストで「窓の保持点を全部除いても屋上まで経路がある」ことを確かめた（窓が閉じても詰まない）
- 2026-11-12 クラシック操作: 方向入力で、その向き ±55° にあり肩から届く最寄りの保持点へ 0.2 秒で手を伸ばし、中立に戻すとつかむ。保持中の手を離せるのは、もう片手が保持中か床に立っているときだけ（両手は同時に離れない）。保持点のない向きなら何もしない
- 2026-11-12 身体は「両手の平均の 0.42m 下（片手なら 0.62m 下）」を目標に、速度上限（1.35m/s×設定）で近づく 1 つの解。肩から手が離れすぎたら、瞬間移動せず同じ速度上限で寄せる（テストで 1 tick の移動が上限以内）
- 2026-11-12 VR 直接操作: 各手の項 = つかんだ瞬間の rig 位置 − (今のコントローラー − つかんだ瞬間のコントローラー)。両手は項の平均（2 倍にならない）。保持の組合せが変わる瞬間は偏り（bias）で連続にして 0.18 秒で戻す。
  1 フレーム 0.3m 超の跳びと追跡喪失からの復帰は、その手をつかみ直した扱い（移動量に使わない）。z は固定（壁の裏や遠方へ行かない）。頭が壁に近すぎると暗転（頭の姿勢は上書きしない）
- 2026-11-12 実機の WebXR では emulatedPosition（位置推定＝追跡喪失）の姿勢は移動に使わない。IWER はコントローラーを常に推定位置として返すので、エミュレーター検証時だけ `?xremu=1` で許可
- 2026-11-12 一時停止からの復帰直後 1.2 秒は、握り直していなくても保持を外さない（復帰直後の落下を防ぐ）。頭の追跡が途切れている間はゲームを進めない（残機は減らない）
- 2026-11-12 描画回数を減らすため、窓まわりは InstancedMesh、外壁は区画ごとの穴あき面を 1 つに結合、人物は部品を頂点色つきで結合、手は指の関節を Bone にした SkinnedMesh 1 つ。結果: 通常 3D で 63〜100 回
- 2026-11-12 室内は 3D モデルを置かず、窓の板 1 枚に光線と箱の交差を計算するインテリアマッピング（両眼でも正しい視差、Quest で軽い）
- 2026-11-12 音は録音・外部サービスを使わず、AY-3-8910 系 PSG をソフトウェアで再現した音源で起動時に合成（曲・効果音）。掛け声はフォルマント合成 → 8kHz・8bit。既成曲は引用しない（参考作品は既成曲を使っていた）
- 2026-11-12 日本語フォントは Noto Sans JP（@fontsource 5.3.1、OFL）から使う文字だけを抜き出して 2 ウェイト計 約 320KB（VR 内のキャンバス文字も確実に日本語になる）
- 2026-11-12 依存の追加なし（ルートの package.json は変更していない）。IWER・fonttools は scratchpad でだけ使った

- 2026-11-12（2 回目の依頼）iPhone/iPad でタッチ操作が効かなかった原因: タッチの受け皿が「一度タッチされた端末」でだけ反応する CSS で、その最初のタッチを受け取れなかった。
  前回の検証は受け皿へ直接イベントを送っていたので見逃した → 実際の指の操作（CDP の Input.dispatchTouchEvent・2 本指）で再現・修正を確認するように変更。
  あわせて、低い画面（スマートフォンの横向き）で操作ボタンが画面外に出る配置を直し、タッチでは「届いたらつかむ」を既定にした（設定で変更可）
- 2026-11-12（2 回目の依頼）キャラクターを作り直し: 距離場（SDF）＋Surface Nets で素材ごとの滑らかな層を作り、骨格とスキンウェイトを付けた一体モデルを
  tools/build-characters.mjs でオフライン生成（src/render/models/*.json・*.bin が制作元データ）。動きは src/render/rig.js のばねで滑らかに。30 項目は docs/CHARACTER.md

## 調整値（推奨初期設定。原作の数値ではない）— src/core/config.js
