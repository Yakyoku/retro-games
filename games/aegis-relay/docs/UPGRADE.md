# AEGIS RELAY 品質向上 — 改善項目 120（キャラクター・背景・サウンド・滑らかさ 各 30）

この作品は Claude（Claude Code のクラウドセッション）で制作しました。

2026-11-13 の依頼「キャラクター・背景・サウンド・画像の滑らかさを、現代のアーケードゲームに匹敵する水準へ。各 30 項目を洗い出して実装し、公開し直す」に対する項目表。
ルール（判定・得点・編隊・難度）は変えない。変えるのは見た目・音・動きの表現だけ。
各項目の実装状況は末尾の「実装結果」に記す。

## D. 滑らかさ（動き・フレーム・輪郭・画面のつなぎ）

| # | 項目 |
|---|---|
| M01 | すべての物体を前 tick との補間でサブピクセル描画（整数に丸めない） |
| M02 | 向き・回転も補間し、実時間のばねで追従（何 Hz でも同じ速さ） |
| M03 | 自機の傾き・炎・軌跡は描画側の実時間で動かす（60Hz の段つきを出さない） |
| M04 | スクロールは前 tick のスクロール量との補間（g.pscroll）で描く |
| M05 | フレーム時計のゆれ取り＋120/144Hz で 1 フレーム 1 回の描画 |
| M06 | 長いフレームの後は追いつきをならす（一度に進めすぎない） |
| M07 | 粒子・文字・輪はオブジェクトを使い回す（GC による引っかかりを減らす） |
| M08 | スプライト・テクスチャ・シェーダーをエリア開始前に作っておく（初めて出る敵で引っかからない） |
| M09 | グラデーション・パターンを毎フレーム作らない（キャッシュ） |
| M10 | 3D: シェーダーの事前コンパイル、エリアの地形生成を時間に分けて行う |
| M11 | 3D: マルチサンプル（MSAA）。XR でもアンチエイリアスを有効に |
| M12 | 2D: スプライトを高い解像度で焼いて高品質に縮小（輪郭のジャギーをなくす） |
| M13 | 回転するスプライトの補間品質を上げる（imageSmoothingQuality） |
| M14 | 速い物体に残像（弾・突進する敵・破片） |
| M15 | 爆発・粒子の動きは実時間（dt）で計算 |

## 実装結果（2026-11-13）

120 項目すべてに実装を入れた。項目ごとの実装箇所・確認方法・できていない点は次の 3 つの記録にある。

| 区分 | 記録 | 担当した項目 |
|---|---|---|
| サウンド | [upgrade/sound.md](upgrade/sound.md) | S01〜S30 |
| 2D 版の見た目・滑らかさ | [upgrade/2d.md](upgrade/2d.md) | C01〜C30、B01〜B30、M の 2D 分 |
| 3D / VR 版の見た目・滑らかさ | [upgrade/3d.md](upgrade/3d.md) | C01〜C30、B01〜B30、M の 3D 分 |
| 共通（shared/） | この節 | M06・M17・M19〜M23 |

共通の滑らかさ:

- M06 `shared/stepper.js`: 長いフレームは 0.1 秒で切り、1 フレーム最大 4 tick、余りは持ち越さない（止まったあとに早送りにならない）
- M17 `shared/app.js`: ヒットストップ（コア撃破 0.12 秒、大型撃破 0.05 秒、被弾 0.09 秒、ボーナス 0.06 秒）。設定で切れる
- M19〜M23 `shared/ui-dom.js`・`shared/ui.css`: HUD は骨組みを 1 回だけ作り数字だけ書き換える、得点のカウントアップ、数字が変わったときの弾み、画面の切り替えのフェード、メニューのスライドイン、ポーズ時の暗転、エリア名の帯のイージング

### 確認したこと

- `node --test tests/*.test.js` 40 項目合格、`node tools/check.js` OK
- headless Chromium（ソフトウェア描画）で 2D・3D のタイトル → プレイ、例外・警告 0（音声 44.1kHz・48kHz の両方）
- 画面キャプチャ: `docs/verification/up2d-*.jpg`・`up3d-*.jpg`
- VR は IWER（Quest 3 の模擬）で開始・操作・ポーズ・再入場
- 3D の描画回数: 通常画面 41〜51 回・三角形 7.8 万〜10.1 万、VR は両眼合計 86〜110 回・15.7 万〜21 万

### 確認できていないこと（数値や画像では代えられない部分）

- **人の耳での試聴**（音色・つり合い・曲の印象）。録音の数値解析のみ
- **Quest 3 実機**での 90Hz、**GPU のある PC の 4K・iPad** での 60fps。コンテナは GPU がなく、fps は測れない
- 動きの印象（アニメーション・爆発・画面の切り替え）は静止画と数値での確認が中心
- 3D の爆発・合体・被弾などの一部の画像は、テストから出来事を注入して撮った（通しのプレイで到達したものではない）
