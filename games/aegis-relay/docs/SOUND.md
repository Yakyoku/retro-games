# AEGIS RELAY 音の資料（設計・音イベント対応表・検証結果）

この作品は Claude（Claude Code のクラウドセッション）で制作しました。

**試聴について**: 制作したセッションではスピーカーで音を聞けない。この資料の「検証結果」はすべて、実際の音源の出力を録って数値とスペクトログラムで調べたもの。音色の好み・音量のつり合い・曲の印象は**人の耳では未確認**。

## 方針

- 曲・効果音はすべて**この作品のために新しく作ったもの**。既存作品・既存アーティストの曲の採譜・編曲・模倣ではなく、録音・サンプル素材・音声ファイル・外部 URL も使っていない。すべて Web Audio で実行時に合成する。
- 音源は 2 種類あり、設定「サウンド」で選べる。初期値はモダン。
  - **モダン**: 減算式シンセ・スーパーソー・FM ベル・サブ入りベース・パッド・アルペジオ＋計算で作ったドラム。ステレオ、残響、ディレイ、サイドチェイン、マスターのコンプレッサーとリミッター。
  - **クラシック（チップ音源）**: 最初の版の音源をそのまま残したもの（矩形波 3 声＋ノイズ 1 声、モノラル、エフェクトなし。曲も最初の版のもの）。
- 2D 版・3D 版・VR 版で同じ音。効果音の左右の定位は盤面の横位置で決める（VR でも頭の向きでは変えない）。

## モダン音源のしくみ

```
曲の 1 音  → 声部の入口 → [ローパス] → [サイドチェイン] → 定位 ─┬→ 世代の出口 → 曲の音量 → ダッキング ─┐
                                                               ├→ 残響へ送る → 共用リバーブ ────────────┤
                                                               └→ ディレイへ送る → 付点 8 分のディレイ ──┤
効果音     → 音量 → 定位（盤面の x）→ 効果音の音量 ─────────────────────────────────────────────────────┤
                                                                                                        ↓
                                              マスター: コンプレッサー → リミッター → ソフトクリップ → 全体の音量 → 出力
旧チップ音源 ───────────────────────────────────────────────（コンプレッサーを通さず）→ ソフトクリップへ
```

- **楽器**（S01〜S06）: スーパーソーは 7 本ののこぎり波（−23〜+22 セント、左右に散らす）を 2 秒のステレオのループ波形に事前計算し、1 音を音源 1 個で鳴らす。リードは 1 オクターブ下の矩形波と、長い音だけ遅れてかかるビブラートつき。ベースはサブ（正弦）＋のこぎり波＋矩形波。プラックとベースの「フィルターが閉じる動き」は、明るい層の音量を素早く下げる形で作る（1 音ごとにフィルターを動かすと重かったため。計測で曲全体の処理時間が約 25% 減った）。
- **ドラム**（S07〜S10）: すべて計算で作る。キック = 音程が落ちる正弦＋クリック、スネア = 胴鳴り 2 本＋ノイズ、ハイハットとシンバル = 倍音関係にない矩形波 6 本＋ノイズ。フィルインとスネアロール（だんだん強く）はセクションの最後の小節に入る。
- **空間**（S11〜S13）: 残響は計算で作った 1.7 秒のステレオのインパルス応答をコンボルバー 1 個で共用。ディレイは曲のテンポの付点 8 分で左右に跳ねる。声部ごとに定位を決めている（アルペジオは左、刻みとハモりは右、ハイハットはやや右、タムは左から右）。
- **サイドチェイン**（S14）: キックの瞬間にパッド（−55%）・ベース（−40%）・刻み（−25%）を沈め、約 0.1 秒で戻す。
- **マスター**（S15）: コンプレッサー（−20dB・3:1）→ リミッター（−5dB・20:1）→ ソフトクリップ（±0.6 まで直線、最大でも ±0.93）。どれだけ音が重なっても出力は ±0.93 を超えない。
- **曲の予約**: AudioContext の時計で 0.5 秒先まで予約する（25ms ごと＋毎フレームに補充）。テンポは描画のフレームレートと関係しない。ポーズ・タブを隠す・VR の非表示は `ctx.suspend()` で、再開すると止めた位置から続く（予約を取り直さない → 二重再生しない）。
- **曲の切り替え**: 曲 1 回の再生ごとに「世代」（声部の配線一式）を作る。止めるときは世代の出口を 12ms でフェードする → 先読み済みの音も一緒に消え、音が残らない。残響の余韻だけが自然に残る。
- **状況で変わる音楽**（S23）:
  - 合体中: 上の層（主旋律の 1 オクターブ上のベル、高いベルのアルペジオ、シェイカー）が加わる。
  - 残り 1 機: 緊張の層（根音と 5 度の 16 分の刻み、低いタムの鼓動）が加わる。
  - どちらの層も基本の層と同じ時間軸に置いてあり、「次の小節の頭から鳴らす／鳴らさない」を切り替えるだけなので、ずれない。
  - エリアコアが近づくと、いまの曲の**次の小節の頭**でコアの曲に切り替わる（上昇音 coreAlert つき）。
  - 開始ジングルはステージ曲の調に合わせて移調してあり、ジングルの終わりの時刻ちょうどにステージ曲が始まる。
- **効果音**（S24〜S29）: 波形は事前計算。再生は「音源 → 音量 → 定位」のノード 3 個。射撃と爆発は毎回、高さ（±0.6〜1.5 半音）と音量（±1dB）と波形の種類を変える。同時発音は全体で 10 まで、音ごとの上限と最短間隔あり。上限に達したら優先度の低い音から止める。大きな音（大爆発・撃墜・合体・ボーナス）の間は曲を 30〜60% 下げる。

## 検証結果（docs/verification/audio-*.png、audio-results.json）

方法: ヘッドレスの Chromium で、ゲームと同じ engine.js を OfflineAudioContext につないで実際の最終出力（リミッターの後）を 48kHz ステレオで書き出し、numpy で調べた。音量はすべて「全体・曲・効果音 = 100%」のときの値（既定の 80%・70%・80% では約 3〜4dB 小さい）。加えて、実際のゲームページ（play2d・play3d）を実時間で動かして確認した。

| 確認したこと | 結果 |
|---|---|
| 音割れ（|x|≥0.999 の標本） | 全 22 本の録音で 0。最大値は 0.726（マスターの最終段の上限は 0.93） |
| 曲の音量（RMS） | title −15.8 / stageA −15.5 / stageB −15.7 / stageC −15.4 / core −15.0 dBFS。ジングルは −16.9〜−18.3。既定の音量では曲＋効果音で −18.8 dBFS・最大値 0.54 |
| セクションごとの音量（stageA） | イントロ −17.5 → A −16.1 → A' −15.5 → B −16.1 → サビ −15.6 dBFS（コンプレッサーでそろうので差は小さい。展開は主に音の厚みで付けている） |
| 帯域の広がり（全体に対する割合、stageA） | 100Hz 未満 −4.8dB / 100〜300Hz −7.5 / 300Hz〜2k −5.0 / 2k〜8k −9.2 / 8k 以上 −13.1。旧チップ音源は 100Hz 未満 −7.8（キックとサブベースが無い）で、スペクトログラムでも拍の間が空いている（audio-songs.png の最下段） |
| ステレオ | 左右の差の成分は和の成分に対して −9.5〜−10.4dB（左右の相関 0.80〜0.83）。旧チップ音源は完全なモノラル |
| ループの継ぎ目 | 模擬の AudioContext で、5 曲とも 3 周目までの**全音符の発音時刻が楽譜と誤差 1ns 未満で一致**（tests/audio-schedule.test.js）。録音でも、2 周目を ±40ms ずらして比べると相関が最大になるのはずれ 0.0ms。継ぎ目の前後 30ms の波形の急変（2 階差分の最大）は、ほかのセクションの頭と同じ大きさ（例: stageA 継ぎ目 0.71 / ほか 0.66〜0.69）→ 継ぎ目だけのクリックは無い |
| 曲の途中の途切れ | 5 曲とも 50ms を超える無音はなし |
| 効果音の嵐（曲の上で 1 秒に 500 回の依頼を 6 秒間） | 最大値 0.726・音割れ 0。3050 回の依頼のうち発音は 275、間引き 2775、優先度による打ち切り 176。嵐の間の音量は −12.2 dBFS、終わると −15.9 に戻る |
| ふつうの密度（射撃 10 発/秒＋撃破） | 曲だけ −15.7 → 効果音つき −15.0 dBFS。射撃 1 発は 50ms の音量で −24dBFS、小さい爆発 −14.6、中 −13.1、大 −10.0、コア −9.6、撃墜 −10.8（曲は −15.5） |
| 左右の定位 | 同じ爆発を左端・中央・右端で鳴らすと、左右の音量差は +16.0 / 0.0 / −16.0 dB |
| 層 | 合体の層・緊張の層とも、頼んだ次の小節の頭から鳴り始め、小節の頭で止まる（テストで時刻を照合。スペクトログラムは audio-adaptive.png） |
| 曲の切り替え | 開始ジングルの終わりの時刻ちょうどにステージ曲の頭（誤差 1ns 未満）。コアの曲は小節の頭から始まり、前の曲はそこを越えて予約されない。停止後は予約が増えない |
| 音源の切り替え | モダン → クラシック → モダンで、切り替えた側だけが鳴る（audio-adaptive.png の最下段）。クラシックの音量は −21.9 dBFS・最大値 0.44（元の 0.55 倍から 0.85 倍に上げてモダンに近づけた。音色は同じ） |
| 実際のゲームページ（play2d、出力 44.1kHz、既定の音量） | ページエラーなし。プレイ中は 1 秒に約 50〜80 個の音源ノードを予約。最大値 0.52・音割れ 0・−19 dBFS。ポーズ中は時計も予約も止まり（2 秒間で発音数 858 → 858）、再開後に続きから鳴る |
| 実際のゲームページ（play3d） | ページエラーなし・音割れ 0。コンテナのソフトウェア描画では画面が毎秒数コマしか出ず、予約が間に合わない音が抜ける（先読み 0.25 秒では −38dBFS まで痩せた。0.5 秒に延ばして毎フレームの補充を足すと −21〜−28dBFS）。ふつうに描画できる実機では起きない見込みだが、未確認 |
| 処理の重さ | stageA を 30 秒書き出すのに 3.2 秒（このコンテナの 1 コアの約 11%）。波形の事前計算はブラウザで合計 0.65 秒（6ms ずつに分けて、最初の操作の前に進める） |

スペクトログラム: audio-songs.png（5 曲＋旧音源）、audio-sfx.png（効果音 29 種・嵐・ふつうの密度）、audio-adaptive.png（層・切り替え・音源の切り替え）、audio-seam.png（ループの継ぎ目と切り替えの拡大）。

**確認できていないこと**: 人の耳での試聴（音色・つり合い・曲の印象・効果音の聞き分けやすさ）。Quest 3 実機・iPad 実機での再生と処理の重さ。Safari では AudioBufferSource の detune が無い版があり、そのときリードのビブラートだけ省かれる（ほかは同じ）。
