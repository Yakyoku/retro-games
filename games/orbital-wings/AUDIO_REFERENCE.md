# AUDIO_REFERENCE.md — 音の方針・つくり・対応・計測結果

## 結論（先に）
- **曲も効果音も、すべてこの作品のために新しく作ったもの。** 既存のゲーム（着想元の 1985 年のアーケード作品を含む）の曲の旋律・効果音は
  再現していないし、収録もしていない。録音素材・外部サービス・生成 AI も使っていない（実行時にブラウザの中で合成する）。
- **人の耳では一度も聴いていない。** 制作環境（クラウドのコンテナ）には音声出力が無い。音色・音量の釣り合い・曲の出来は、
  書き出した波形の**数値の点検だけ**で決めた（下の「計測結果」）。聴感としての良し悪し（心地よさ、音色の好み、ゲーム内での聞こえ方）は**未確認**で、
  公開版を実際の端末（ヘッドホン・スピーカー・Quest 3）で聴いて直す必要がある。
- 2026-11-13 に音源を刷新した。既定は新しい**「モダン」音源**。従来の PSG・波形メモリ音源は**「レトロ音源」**として残し、設定の「音源」で切り替える
  （旧「アレンジ」設定は廃止。保存済みの値は読み込み時に捨て、音源は `soundEngine` で選ぶ）。

## モダン音源（既定。shared/audio/modern.js ほか）
| 部品 | 中身 |
|---|---|
| 曲の声（最大 32） | 4 オペレーター FM（5 アルゴリズム、フィードバック）／仮想アナログ（鋸・矩形・PWM・三角・サイン・スーパーソー 3〜7 本・波形メモリ・ノイズ、polyBLEP で折り返しを抑制） |
| 音色の動き | 状態変数フィルター（LP/BP/HP）＋フィルターエンベロープ・LFO・キー追従、音量 ADSR、ビブラート、ポルタメント、ピッチベンド、ドライブ |
| 打楽器 | 合成: キック（高さが落ちるサイン＋クリック）、スネア（胴 2 音＋ノイズ）、ハット閉・開（金属 6 本＋ノイズ、同じ声で打ち消し）、クラッシュ、ライド、タム高・低、リム、クラップ（3 連打＋尾） |
| 低音 | FM ベース／鋸・矩形＋サブ。キックのサイドチェインで下がる束に入る（和音の層も） |
| 定位 | 声ごとに左右、スーパーソーは左右に広げる。低音・キック・スネアは中央 |
| 空間 | 残響（8 本の遅延線の FDN、ハウスホルダー行列、前置き遅延・拡散・高域減衰）とテンポ同期のピンポン・ディレイ。どちらもセンド |
| マスター | 曲の高域の持ち上げ → 直流カット → バス圧縮（2:1）→ ソフトクリップ → 先読みリミッター（2.5ms、上限 0.85） |
| 効果音 | 専用の声（最大 48 層・同時 12 個）。サイン・三角・鋸・矩形・ノイズ・FM・金属・破片の層を重ねる。優先度で奪い合い、曲の声は奪わない |
| 進行 | tick（4 分音符 = 24）単位、境目は標本の精度。制御は 64 標本ごと。音の計算の中では配列・オブジェクトを作らない |

### 動的な曲・場面の転換
| 仕組み | 動き | ゲーム側（shared/app.js） |
|---|---|---|
| 強さ `setIntensity(0〜2)` | 1 で 16 分の高い分散和音＋ライド、2 で裏拍の和音の一打が加わり、テンポが 4〜5% 上がる | ボスの体力 65% 未満で 1、30% 未満で 2。最終ボスはフェーズ 2 で 1、フェーズ 3 で 2 |
| 層 `setLayer('danger')` | 高い 8 分の刻み＋低いタムの鼓動 | 本編で残機が最後のとき |
| 開始ファンファーレ | `start`（2 小節）を面の調とテンポに移して鳴らし、切れ目なく面の曲の前奏へ | 面の開始（復帰のときは付けない） |
| 曲の切り替え | 前の曲をフェード＋ローパスで消してから次へ。ボス曲の入りに一打（stinger）と登場の重低音 | ボス出現・撃破・クリア |
| 一時停止 | 曲は止めずにこもらせ（約 520Hz のローパス、-7dB）、鳴っていた効果音は消す。解除で戻る | 一時停止メニュー |
| ゲームオーバー | テープを止めるように約 0.9 秒で高さと速さを落としてから gameover の曲へ | 残機 0 |
| ダッキング | 大きな効果音（爆発・警告・ミスなど）の間、曲を 8〜60% 下げてゆっくり戻す | 自動 |
| 効果音の定位 | 画面上の x 位置で左右へ（最大 ±0.5）。2D・3D・VR で同じ（VR でも頭の向きには追従しない。BGM・UI は中央） | 出来事の x と画面の左端から計算 |

## 効果音とイベントの対応（すべて新規作成。名前は従来のまま＋追加）
| 効果音 | 鳴る時 | 優先度 |
|---|---|---|
| shot / double / laser / missile | 1 回の斉射につき 1 回（オプションが何機でも）。高さを順にずらして連射の単調さを避ける。同じ音は重ねない | 2〜3 |
| capsule（= gauge） | カプセル取得。ゲージの位置（6 段）で音階が上がる | 5 |
| powerup_speed / _missile / _double / _laser / _option、shield_on | 装備の確定（装備ごとに別の音）。powerup は汎用 | 6 |
| deny | 取得できない | 5 |
| shield_hit / shield_break | シールドで防いだ（残りが少ないほど低い）／最後の 1 枚が割れた | 4 / 6 |
| enemy_hit | 耐久のある敵に当てた | 1 |
| explode_s / explode_m / explode_l | 小・中・大の撃破（毎回高さと音量を少し変える） | 3 / 4 / 5 |
| turret_fire / ring / tentacle | 砲台・砲の発射／石像のリング弾／触手の発射 | 1 / 3 / 2 |
| piston_slam / zap_warn / zap_beam / cell_pop | 押しつぶし柱が伸びきった／光線の予告／照射／細胞の破裂 | 3 / 3 / 4 / 2 |
| boss_enter ＋ stinger | ボス登場（重低音と一打） | 7 |
| boss_telegraph / boss_beam / boss_attack | ボスが待機から攻撃の構えに入った／ビーム／全方位弾 | 6 / 6 / 4 |
| part_destroyed / phase_change / boss_explode | 部位破壊／最終ボスのフェーズ移行／撃破の連鎖爆発（約 3.8 秒） | 6 / 7 / 8 |
| player_die | ミス | 9（最高） |
| warning | ボス接近 | 7 |
| cursor / select / cancel / pause / resume / start | メニュー（同じ FM の音色・同じ調で統一） | 2〜7 |
| extend / checkpoint | 定義のみ（現在のゲームからは呼んでいない） | 7 / 4 |

レトロ音源では、追加した効果音は従来の音に読み替える（`sfx2.js` の `RETRO_ALIAS`。例: zap_beam → laser、part_destroyed → explode_m、phase_change → warning。
対応の無いもの＝砲台の発射・予告音・登場音などは鳴らさない）。したがってレトロ音源での鳴り方は従来と同じ。

## レトロ音源（従来のまま。shared/audio/chip.js・songs.js・sfx.js）
着想元の時代の**基板の音源構成**だけを模擬したもの（曲・音そのものは模擬していない）。
| 部品 | 模擬 | 用途 |
|---|---|---|
| PSG-A（AY-3-8910 相当） | 矩形波 3＋共有ノイズ（17bit LFSR）＋エンベロープ、12bit 周期、対数音量表、クロック 1.789772MHz/16 | 曲 |
| 波形メモリ 2 音（K005289 風） | 32 サンプル × 4bit、12bit 周期、4bit 音量 | 曲（ベース・対旋律） |
| PSG-B（2 個目の AY-3-8910 相当） | 同上 | 効果音専用 |
| 出力 | 2 段ローパス約 8kHz → 直流カット → ピーク抑制、モノラル | |

参照した資料（2026-11-12 に読んだもの）: MAME `src/mame/konami/nemesis.cpp`（音声 CPU のクロック、AY8910 ×2 と K005289 の構成を確認。クロックと出力がモノラルである点は要約のみで逐語は未確認）。
原作の音源を試聴・比較はしていない。レトロ音源の一時停止は従来どおり「曲を止めて消す」。

## 計測結果（機械による確認のみ。2026-11-13、`node tools/render-audio.js` と `node --test tests/audio.test.js`）
すべて 48kHz ステレオ、音量設定 100% での値。数値は `audio-masters/report.json` にも保存。

**曲（モダン音源）**
- 統合ラウドネス（BS.1770、K 特性＋ゲート）: -15.0 〜 -14.2 LUFS（幅 0.8 LU。目標 -15 ±1.5）。曲ごとの補正は `songs2.js` の `trim`。
- ピーク 0.85（リミッターの上限）、真のピーク（4 倍補間）最大 0.94、クリップ 0、NaN 0、直流 4e-6 以下。
- オクターブ帯域（全体に対する dB、ループ曲の典型）: 63Hz -6／125Hz -6／250Hz -10／500Hz -10／1kHz -9／2kHz -13／4kHz -16／8kHz -20／16kHz -23。
  低域が抜けたり高域がきつかったりする曲は無い（gameover だけは意図して暗い: 4kHz -28dB）。
- 左右の相関 0.86〜0.95（2 秒窓の最小 0.80）。モノラルにしても痩せない。
- ループ: 1 周目と 2 周目の長さは同じ（±64 標本以内）、音量差 0.05 LU 以下。全トラックの長さ・ループ点が一致、全小節が 96 tick。
- 曲の作り: 調の中の音 95〜100%（ファンファーレは借用和音のため 72%）。旋律の強拍の音が和音の音である割合 79〜100%、半音でぶつかる音 0〜6%（経過音・倚音）。
- 同時発音: 曲だけで 13〜20 声、声が足りなくなった回数 0。

**効果音（モダン音源）**
- 最大瞬間ラウドネス（400ms）: 連射 shot -32／爆発 小 -23・中 -17・大 -14／カプセル -18／装備確定 -16〜-20／メニュー -17〜-18／警告 -13／
  ボスのビーム -11／ボス撃破 -11／ミス -11 LUFS。曲（-15）に対して、頻繁な音は小さく、重要な音は大きい並び。
- 連射（shot 毎秒 10 回）: 連射だけで -25.9 LUFS（曲より 11.8 LU 小さい）。曲に重ねても全体は +0.3 LU。shot は常に 1 つしか鳴らない。
- 最大の重なり（ボス曲＋強さ 2＋danger＋効果音を毎フレーム 4 種、声 71）でもピーク 0.852、NaN 0。

**場面**
- 動的な層: 強さ 1 で +1.1 LU、2 で +1.3 LU、danger で +0.4〜0.7 LU（ボス曲・最終ボス曲・1 面）。
- 一時停止: 2kHz より上が 31dB 下がり、350Hz より下は 6.5dB 下がるだけ。解除で元に戻る（差 0.3dB）。曲の位置は止めなかった場合と一致。
- 開始ファンファーレ → 面の曲: 60ms 窓の最小 RMS 0.039（無音の窓 0）。テープストップ → gameover: 段差（クリック）なし。
- 止め際・切り替え・音源の切り替えで NaN・クリップなし。同じ操作なら出力は完全に一致（決定的）。

**計算時間（Node 22、Xeon 2.1GHz の 1 コア、CPU 時間。計測中は同じ機械でほかの処理が多数動いていたので、値は大きめに出ている可能性がある）**
- 曲だけ: 1.9〜3.0%（実時間に対して）。ふつうの場面（3 面の曲＋射撃・爆発）: 約 3〜5%。
- いちばん重い現実的な場面（ボス曲・強さ 2・danger＋射撃・爆発・ビーム、声 41）: 約 6%。
  あり得ないほど詰め込んだ場面（効果音を毎フレーム 4 種、声 71）: 約 7%。無音: 0.45%。
- 音の計算の中の確保: 慣らしたあと 120 秒ぶん計算して GC 0 回。発音の開始など回数の少ない処理が JIT で最適化されるまでは、一時的な数値の箱が少量（1KB/秒未満）作られることがある。
- Quest 3 の実機での負荷は**未計測**（`audio.state.load` に音の計算の割合が出るので、公開版で確認できる）。

**ブラウザ（Playwright、Chromium）**
- 2D・3D とも: ページエラーなし、音声は unlock 済み・running、曲の位置が進む、実際の出力（AnalyserNode）の RMS > 0、
  面の開始でファンファーレ → 面の曲、ボスで boss の曲と強さ 2、設定の「音源」でモダン ⇄ レトロが切り替わり保存される、
  一時停止中も曲が進む、タブを隠すと止まり戻すと続きから。これはリクエスト差し替えのため ScriptProcessor の経路での確認。
- AudioWorklet の経路は、`file://` で開いた Chromium（`--allow-file-access-from-files`）で `backend: 'worklet'`・発音・音源の切り替えを確認した。
  公開版（HTTPS）と Quest Browser・iOS Safari での確認は未実施。

## 未確認・既知の点
- 聴感（音色の良さ、旋律と伴奏の聞こえ方、効果音のうるささ、残響の量）は未確認。数値は「壊れていない・そろっている」ことしか保証しない。
- 編曲の和音の層・分散和音・低音・打楽器は和音名と型からの自動書き出しなので、機械的に聞こえる箇所があるかもしれない。
- 計算時間は端末で変わる。重ければレトロ音源に切り替えられる。
